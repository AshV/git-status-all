The Problem

Working with Microservices or Many Projects?

When you have dozens of repositories scattered across your machine, keeping track of which ones have uncommitted work, untracked files, or unpushed commits becomes a nightmare. Running git status in every single folder is tedious and time-consuming.

git status -all solves this by recursing through your directories, finding all valid Git repositories, and giving you a comprehensive, beautifully formatted status report.

User Guide

Running on Windows (PowerShell)

The PowerShell version is highly optimized and offers the best feature set.

# Basic scan in current directory
.\git-status-all.ps1

# Scan a specific directory
.\git-status-all.ps1 -Directory "C:\MyProjects"

# Export results to Markdown
.\git-status-all.ps1 -Export md

# Export results to JSON and CSV
.\git-status-all.ps1 -Export json,csv

Running on Linux/macOS (Bash)

Use the bash script for a fast, Unix-friendly experience.

# Make it executable
chmod +x git-status-all.sh

# Basic scan
./git-status-all.sh

# Scan a specific directory
./git-status-all.sh -d ~/Projects

Running on Windows (Command Prompt)

If you prefer the classic Windows Command Prompt, a lightweight batch script is also available. 

:: Basic scan in current directory
git-status-all.bat

:: Scan a specific directory
git-status-all.bat "C:\MyProjects"

Setup an Alias

Run it from anywhere

Instead of typing the full path to the script every time, set up an alias in your terminal to run it with a quick command like gsa (Git Status All).

PowerShell Profile

# Open your profile
notepad $PROFILE

# Add this function to the file and save
function gsa { & "C:\path\to\git-status-all.ps1" @args }

Bash / Zsh (.bashrc / .zshrc)

# Open your configuration file
nano ~/.bashrc

# Add this alias to the bottom
alias gsa='/path/to/git-status-all.sh'
